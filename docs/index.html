labdev.lib

A C++17 library of laboratory instrument drivers that publish every reading as a Prometheus gauge.

C++17 Prometheus metrics Ethernet · Serial · EtherCAT MIT
Get started View on GitHub

Why labdev.lib

Temperature controllers, vacuum gauges, cryocoolers and DAQ behind one small interface.

One interface

Every instrument is a labdevices: construct it, call update(), read gauges.

The gauge is the cache

update() pushes values to Prometheus and getGauge() reads the last one back. No shadow state.

Faults stay local

The optional DeviceManager isolates failures, so one dead instrument never stops the others.

Cheap to extend

A new instrument is one class and one small Makefile.

Every gauge carries the label {Component="<device name>"}, so two devices can both expose a gauge named A.

Cooler control

Three devices switch their cooler or compressor with the same method names.

DeviceMethodsSuccess means
sunpowerDS30setCoolerOn() / setCoolerOff()the command got a reply
sunpowerMTsetCoolerOn() / setCoolerOff()the reply confirms ON / OFF (old set_cooler_on/off() still work)
coolpaksetCoolerOn() / setCoolerOff()the reply confirms the new state; SYSTEM ERROR gives false
 
auto cp = manager->getDevice<coolpak>("D_Coolpak");
if (cp && !cp->setCoolerOn())
  std::cerr << "compressor did not start\n";
Concurrency. coolpak serialises its serial exchanges with a mutex, so the command can be sent while the device is being polled. For the sunpower devices, call disableDevice(name) first and enableDevice(name) afterwards.

Quick start

You do not need DeviceManager. Poll a device yourself.

#include <labdev/lakeshore336.h>
#include <prometheus/exposer.h>
#include <prometheus/registry.h>
#include <iostream>
#include <thread>

int main() {
  prometheus::Exposer exposer{"0.0.0.0:9878"};
  auto registry = std::make_shared<prometheus::Registry>();
  exposer.RegisterCollectable(registry);

  // IP, port, device name, extended inputs, registry
  lakeshore336 ls("192.168.1.50", 7777, "D_Lakeshore", true, registry.get());

  for (;;) {
    ls.update();                    // read the instrument, push gauges
    if (ls.isOnline())
      std::cout << "A = " << ls.getGauge("A") << " K\n";   // read back the cache
    std::this_thread::sleep_for(std::chrono::seconds(1));
  }
}

Point Prometheus at host:9878/metrics. Link with:

g++ -std=c++17 app.cpp -o app \
    -llabdev -luics -lsoem -lprometheus-cpp-pull -lprometheus-cpp-core -lpthread
# -lsoem is only needed if you use gauge972_e

DeviceManager

A ready-made polling loop for applications. The drivers never use it themselves.

Use it when you have several devices and want one background thread polling all of them at their own interval, fault isolation (a device that throws repeatedly is disabled instead of killing the loop), runtime control, and automatic online/offline logging for every device.

        DM->>Dev: update()
        alt reading OK
            Dev->>Reg: setGauge(name, value)
            Note over Dev: online = true
        else failure
            Note over Dev: online = false
        else throws
            DM->>DM: errorCount++ (disable after N)
        end
        DM->>DM: log only if online state changed
    end
    App->>Reg: scrape / getDeviceValue()

auto exposer  = new prometheus::Exposer("0.0.0.0:9878");
auto registry = std::make_shared<prometheus::Registry>();

// default poll interval 5 s
auto manager = new DeviceManager(registry.get(), std::chrono::milliseconds(5000));

auto pressure  = std::make_shared<gauge972_e>("/opt/app/config/mks972b.cfg",
                                              "D_Pressure", registry.get());
auto lakeshore = std::make_shared<lakeshore336>("/opt/app/config/lakeshore.cfg",
                                                 "D_Lakeshore", -1, true, registry.get());
auto sunpower  = std::make_shared<sunpowerDS30>("/opt/app/config/sunpower.cfg",
                                                 "D_Sunpower", registry.get());

exposer->RegisterCollectable(registry);
manager->addDevice(pressure);
manager->addDevice(lakeshore, std::chrono::milliseconds(2000));  // custom interval
manager->addDevice(sunpower);
manager->start();
double p;
if (manager->getDeviceValue("D_Pressure", "D_Pressure_Pressure", p) &&
    manager->deviceOnline("D_Pressure"))
  std::cout << "pressure: " << p << " Torr\n";

manager->disableDevice("D_Lakeshore");
manager->setDevicePollInterval("D_Sunpower", std::chrono::milliseconds(10000));
manager->enableDevice("D_Lakeshore");

for (auto &name : manager->getDeviceNames())
  for (auto &g : manager->getDeviceGaugeNames(name))
    std::cout << name << " -> " << g << "\n";

manager->setErrorCallback([](const std::string &dev, const std::string &err) {
  std::cerr << dev << ": " << err << "\n";
});
MethodPurpose
addDevice / removeDeviceRegister or drop a device. Interval 0 uses the default.
start / stop / isRunningControl the polling thread.
enableDevice / disableDevice / isDeviceEnabledPause one device without removing it.
setDefaultPollInterval / setDevicePollInterval / getDevicePollingTimePolling cadence.
setMaxErrorsBeforeDisableConsecutive throws before auto-disable.
deviceOnline / deviceExistDevice state.
getDeviceValue / getDeviceGaugeNamesLast value read, no I/O.
getDeviceNames / getDeviceCount / getEnabledDeviceCount / getDeviceErrorCountInventory and health.
setErrorCallbackBe notified of device exceptions.
getDevice<T>Typed access to call device-specific methods.
Thread safety. getDevice<T>() hands you the device, and what you call on it runs on your thread while update() may be running on the polling thread. The transports are not mutex protected. If the call does I/O, call disableDevice(name) first and enableDevice(name) afterwards.

Writing a new device

One class, one Makefile.

  1. Create src/devices/<name>/ with a Makefile copied from lakeshore-336.
  2. Add the directory to both all: and clean: in src/devices/Makefile.
  3. Derive from labdevices plus a transport (ethernet_device, serial, or nothing).
  4. Call addGauge(name, description) for every reading in the constructor.
  5. Override update(): online = true on entry, setGauge(...) per reading, online = false on failure. Return quickly.
  6. Offer an explicit constructor and a config-file one using cfg_get_int / cfg_get_string.
class mydevice : public labdevices, public serial {
public:
  mydevice(int port, int baudrate, std::string name, prometheus::Registry *reg)
      : labdevices(name, reg) {
    addGauge("Temperature", "Sensor temperature (K)");
    status = ouvrirport(port, baudrate);
  }

  void update() override {
    online = true;
    std::string reply = communicate("TEMP?\r", 64, true);
    if (exchange_status != VALID) { online = false; return; }
    setGauge("Temperature", std::stod(reply));
  }
};

Logging

A daily log goes to /var/tmp/labdev/yyyymmdd.txt (GMT, default level LOG_INFO). Readings and per-transaction I/O are never logged. Faults in polling loops use labdev::log_latch, which writes once when a fault starts and once when it clears.

#include <labdev/labdev_log.h>
labdev::log_set_path("/var/log/myapp/labdev/");  // before constructing any device
labdev::log_set_level(labdev::LOG_WARN);         // -1 silences the log

Build and install

Needs a C++17 compiler, prometheus-cpp and SOEM (submodules), and UICS. The optional LabJack device also needs the LJM SDK.

git clone --recurse-submodules https://github.com/espressjo/liblabdev && cd liblabdev

# once: dependencies
cd external && make clean all && sudo make install && cd ..

make all            # builds into ./build
make all            # a fully clean build needs this twice
sudo make install   # /usr/local/lib and /usr/local/include
Gotchas. A fully clean build/ needs make all twice, because the root Makefile expands $(wildcard build/*.o) before anything is compiled. Stale .o files get linked in, so run make clean after removing or renaming a source file. build/include/labdev.h is generated, never edit it.
